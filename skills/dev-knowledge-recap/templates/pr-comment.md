### 1. Concurrency vs. Parallelism `concurrency`
<sub>Seen in `src/api/user.ts`</sub>

**Principle**
- Concurrency: multiple tasks in progress, interleaved. Parallelism: multiple tasks executing at the same instant.
- JS runs on one thread. I/O is handed to the runtime; the event loop picks up results as they finish.
- `Promise.all` starts every request up front, so the waiting overlaps: total time ≈ slowest request, not the sum.

**Trade-offs**
| Pros | Cons |
|---|---|
| Lower latency for independent I/O | Fails fast: one rejection rejects all |
| No threads or locks | No speedup for CPU-bound work |

**Alternatives**
| Option | Use when |
|---|---|
| Sequential `await` | Each step depends on the previous one |
| `Promise.allSettled` | Partial failure is acceptable |
| Concurrency limit (`p-limit`) | Many requests; protect the server |
| Worker threads | CPU-bound work |
