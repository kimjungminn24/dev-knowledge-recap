## Dev knowledge behind this PR

### 1. Signals and graceful shutdown `os`
<sub>Seen in `.github/workflows/deploy.yml`, `deploy/pik-one-backend.service`</sub>

**Concept**
- A signal is a notification the OS sends to a process
- SIGTERM: clean up and exit. SIGKILL: die immediately

**Principle**
- SIGKILL (`kill -9`) can't be caught: in-flight requests are dropped, DB connections are left open
- `systemctl restart` sends SIGTERM first, so JVM shutdown hooks run
- A process killed by signal N exits with 128 + N. SIGTERM (15) -> 143, hence `SuccessExitStatus=143`

**Trade-offs**
| Pros | Cons |
|---|---|
| No half-written state | Slower stop; a hung app still needs SIGKILL |

**Alternatives**
- `server.shutdown=graceful`: finish in-flight requests before exiting
- `TimeoutStopSec`: cap how long a graceful stop may take
